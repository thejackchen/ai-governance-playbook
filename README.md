# AI Governance Playbook

## 北极星(负责人 2026-07-28 定纲;每次评估对着这三条打勾)

> **对任何一个项目——不管是新建的,还是中途加入的——只要对 AI 说一句「参考我的 AI governance」并甩出本仓链接,它就必须得到一致的治理水平:每一轮对话的要点全部记载,随时可以无缝切换到另一个 AI 接手,不需要负责人重新讲一遍。**

可检验的三条验收(任何项目、任何时刻可查):
1. **装没装**:项目根有 `governance.lock.json` 且 `doctor.mjs --target <项目>` 绿——没有 = 没装或手工抄(手工抄必漏 hook,见判例 2026-07-28);
2. **守卫在不在岗**:hook 载体真实生效(claude-code 看 `.claude/settings.json` 含 Stop;codex 看 `.codex/hooks.json`)——`governance-lint` 校验;
3. **能不能无缝接手**:新 AI 只读 宪法→知识索引→ROADMAP 游标 三件套即知当前实况——游标新鲜度由收尾纪律 + lint 保证。
4. **终极验收 = 空白对话冷启动考试**(负责人 2026-07-28 定,可随时突袭):对该项目开一个**全新零上下文**的 AI 会话,只说「读本仓治理接手」,然后问四题——①当前在干什么、哪些战线活跃?②最近三天做了什么重要决策?③本项目红线有哪些?④你接手后下一步该做什么?**负责人对照实况判卷:四题全对=达标;任一题答不上或答成旧状态=对应环节的落盘断了,顺断点修**。前三条是静态前置检查,这一条是端到端直接测量(同源思想:本仓历来「经无记忆 AI 实测发布」)。


给 AI 主导的项目装一台「治理恒温器」:规则不靠文档自觉,靠机器载体执行;经验不靠人记,靠判例沉淀。**版本 v3.7.4(见 VERSION)。线上是通用母版；消费仓开机按项目事实适配编译，项目自己的验证器通过后才给 Codex、Claude Code、Grok 签发同一张施工许可。**

## 负责人口令表(四句覆盖所有场景,复制粘贴即用)

| 场景 | 你说这句 | 背后发生什么 |
|---|---|---|
| 让某个 session **收尾**(干完了/要挂起) | 「收尾 landing:把本 session 的决策/设计全部落盘(docs + ROADMAP 线行 + CHANGELOG),没定稿的记 questions,把落盘清单报我。」 | 它走 landing 五步,Stop hook 兜底结构门 |
| 压缩/换工具/**重启前收口** | 「收口:停新功能,离开 /tmp,提交要留的改动,把目录/分支/HEAD/下一步写入仓内正本。」 | PreCompact 只注入坐标；这句话才真正落盘 |
| **查账**(不确定落没落) | 「按 landing 五步自查:哪些落了、哪些没落,列清单,别动手先报告。」 | 只查不改,给你差异清单 |
| 新开 session **接手** | 「读本仓治理接手。」 | 自动 boot:宪法→总纲→游标,零重讲 |
| **新项目/中途加入的项目** | 「参考我的 AI governance:本仓链接,按 setup.md 安装,交安装报告。」 | init 装全套 + lock 登记,北极星四验收可查 |

规律:干活说「接手」,交账说「收尾」,不放心说「自查」,新项目甩链接。四句之外不需要记任何东西;随时用北极星第 4 条(空白对话四题考试)突袭验收。

## 怎么用(负责人只需要这一段)

把这句话交给任何项目的 AI:

> 读 https://github.com/thejackchen/ai-governance-playbook 的 setup.md,先通读 governance/cases/ 判例库,再为本项目建立治理(存量项目走 setup 附A);完成后按 setup 附B 自检,向我交付安装报告。

之后你的参与只有三种:确认它提交的意图/红线、回答它升上来的问题、每次纠正它(纠正会变成判例,所有项目共享)。

## 里面有什么(文件地图)

| 文件/目录 | 给谁 | 干什么 |
|---|---|---|
| README.md(本页) | **人** | 唯一需要人读的页 |
| BOOTSTRAP.md | **零上下文 AI** | 从无 playbook 到标准治理骨架的单一入口 runbook |
| CORE.md | AI | 方法论权威(控制回路/五个结构问题/载体规范+运行时适配) |
| setup.md | AI | 安装流程(+附A 存量迁移/附B 验收自检) |
| governance/cases/ | AI | **判例库(12 条)——历次真实教训,新项目安装第一步通读** |
| profiles/ · adapters/ · templates/ | AI | 三档规格 · 运行时适配 · 安装模板 |
| extensions/frontend-design-system/ | AI | 可选前端设计系统扩展；按需安装；设计语言正文留在项目架构，`representativeJourneys` 让采用范围和证据可被 AI/机器看到 |
| scripts/ | 机器 | init 安装器 · doctor 体检 · verify 校验 |
| governance/ 其余 · ROADMAP · CHANGELOG | 机器+AI | 本仓库自己的治理(自食其力) |

## 原则(一行)

能简单绝不复杂;规则必须说清解决什么结构问题,说不清不装;负责人看不懂 = 最高优先级事故。
