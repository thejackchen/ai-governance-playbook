# {{PROJECT_NAME}} Reference Pack

参考包属于产品架构的设计输入，不是治理规则，也不提供一套跨项目的默认审美。

## 选择状态

- 生命周期以 `governance/frontend-policy.json` 为唯一机器权威。
- `reference-pending` 表示项目尚未用代表页面、真实状态、可访问性和运行端证据确认可执行基线；参考来源可以未选定，也可以已经提出候选。
- 选择参考后，在本页记录来源、名称、版本或日期，以及允许借鉴和明确不采用的部分。

## 三层来源

### baseSystem

大厂设计系统或成熟基础设计系统的参考来源。它不能只作为换色皮肤使用，必须经过项目语义层映射：信息角色、组件意图、状态、密度和交互边界仍由本项目定义。

- 来源、名称与版本：由项目负责人填写。
- 借鉴的基础原则：由项目负责人填写。
- 项目语义层映射：由项目负责人填写。

### industryPatterns

行业/电商页面模式的参考来源，用于记录任务流、信息组织、筛选/比较/下单等页面模式。

- 来源、场景与版本或日期：由项目负责人填写。
- 借鉴的页面模式：由项目负责人填写。
- 不采用的模式：由项目负责人填写。

### brandLayer

项目自身的品牌层，用于记录项目色彩、资产和信息角色，不把外部参考误当成项目品牌正本。品牌手册、官网和 Logo 中观察到的颜色属于来源证据，不自动成为按钮、部门、状态或价格等 UI 语义；必须经过项目语义映射、对比度和代表页面验证。

- 项目色彩与语义角色：由项目负责人填写。
- 来源色与 UI 语义色的映射及排除项：由项目负责人填写。
- 项目资产来源与使用边界：由项目负责人填写。
- 信息角色、语气与优先级：由项目负责人填写。

## 参考边界

参考来源不是复制资产。不得把第三方 logo、字体、图片、图标、代码、截图或组件实现直接复制为本项目资产；只记录可追溯的原则、模式和语义映射。

治理只验证本页存在、三层来源结构和 policy 路径；视觉判断、参考选择和最终取舍仍属于产品架构决策。
