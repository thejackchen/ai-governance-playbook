# 运维通道用过即登记

- **来源**：AIOS · 2026-08-29 · 负责人当场纠正（主 agent 找不到 Mini SSH 通道，负责人指出该通道在多个环境里反复用过，属登记缺口）
- **场景**：部署前需要连边缘执行机。仓外正本索引里只有一条泛泛的「~/.ssh/config 存在（含 shdev 等 Host）」，没有该执行机通道的专项条目；换了主 agent 之后只能报「正本未装载」并向负责人求助，而通道事实上早已存在且被多环境反复使用。
- **执行者做法**：把「索引里没有」当成「本机没有」，停在向负责人要通道；把 SSH 配置文件的存在性条目误当成了通道登记。
- **负责人要的做法**：一边做项目一边补治理缺口，当场收口：实测每条候选通道（隧道/局域网/Tailscale 逐一验证并标注失效项）→ 通道细节写进 `~/.config/<域>/` 仓外正本文件（600 权限，含用法与红线，不含口令）→ 在 `extra-repo-facts.json` 登记专项条目 → 推上公共线 → 教训泛化回母版。
- **可泛化边界**：任何在真实作业中实际使用过的运维通道与凭据位（SSH 别名、跳板、反向隧道、边缘执行机、面板口令位置）都必须在首次使用时登记为专项仓外事实；「存在性条目」（某配置文件在）不等于通道登记。发现口头相传、散落多环境的事实没有索引条目，按登记缺口处理：先补索引与正本，再继续原任务。
- **载体**：模板仓外正本指引「以后每个 AI 必须遵守」新增第 6 条「用过即登记」（v3.7.6）；首例 = AIOS `mini-ssh-channel` 条目与 `~/.config/aios/mini-channel.md`。
