# 凭据的忽略规则必须覆盖派生形态:六个仓四个漏

- **来源**:微信客服 · 2026-07-25。从一个残留 worktree 里发现未被忽略的 `.env.local.bak`,顺手排查了手头全部六个仓库。
- **场景**:各仓 `.gitignore` 都规规矩矩写了 `.env` / `.env.local` / `.env*.local`,看上去凭据保护到位。但**派生形态不在覆盖范围内**——`.bak` / `.old` / `.save` / `~` 这些后缀是加在末尾的,`.env.local` 这条规则匹配不到 `.env.local.bak`。

| 仓 | `.env.local` | `.env.local.bak` |
|---|---|---|
| A(客服) | ✅ | ✅ 本就用 `.env.*` |
| B(老仓) | ✅ | ✅ |
| **C(go-forward 主仓)** | ✅ | ❌ **且盘上真有这个文件,含 8 处凭据特征** |
| D | ✅ | ❌ |
| E | ✅ | ❌ |
| **F(知识库)** | ❌ | ❌ **一条 env 规则都没有** |

- **执行者做法**:看到 `.gitignore` 里有 `.env.local` 就认为凭据已被保护,不验证派生名。
- **负责人要的做法**:
  1. **用通配覆盖整族,再显式放行需要入库的**——`.env.*` + `!.env.example`,而不是逐个列举可能的名字(列举永远漏);
  2. **验证方式是 `git check-ignore <名字>`,不是读 `.gitignore`**——读规则是"我以为",check-ignore 是"确实挡住了"(同族:[成功信号本身要被验证](2026-07-25-成功信号本身要被验证.md));
  3. **写成机器门禁而非文档**——枚举 `.env.local.bak/.old/.save/~` 逐个 check-ignore,任一漏掉即 error。红线不该靠人记着。
- **为什么必然发生**:造这类文件的**不是人的疏忽,是工具的日常行为**——编辑器写 `~` 备份、手工 `cp .env.local .env.local.bak` 再改、恢复脚本落 `.save`。**规则写的是"我打算创建的文件名",而漏的是"工具替我创建的文件名"**。二者永远对不上,除非用通配。
- **可泛化边界**:适用于一切**按名字保护**的规则——`.gitignore`、密钥扫描白名单、备份排除表、日志脱敏字段名。凡"列举具体名字"的地方,都要问一句:**派生形态呢?**
- **载体**:机器门禁(逐个 `git check-ignore` 断言,error 级)。安装到新项目时应随治理套件一起落地。
