# 仓外正本没有仓内指针就会被替身止搜

- **来源**：AIOS · 2026-08-23 · 负责人当场纠正（Demo 人名对照在家目录，另一 AI 拿租户台账止搜）
- **场景**：口令、网关密钥、真人身份对照不能进 git。索引和 SessionStart 原先只覆盖仓库内 `docs/`。仓内另有一份看起来完整的台账，覆盖范围其实更窄。
- **执行者做法**：把 `tenants.json` 当成 Demo 人名正本；或把对照表只写在某一个工具的 memory 里。换模型、压缩上下文后，事实蒸发，搜索停在替身文件。
- **负责人要的做法**：Git 里必须有只写路径的索引；开工注入在/缺，永不打印仓外文件内容；替身文件声明自己不管什么；正本未装载就报未装载，禁止用替身凑答案。
- **可泛化边界**：凡是「真源在仓外」的事实类都适用。不是「把秘密写进 git」，也不是「每个项目必须有仓外秘密」——无此类事实时索引可为空列表，但机制必须在。
- **载体**：`docs/ops/extra-repo-facts.json` + SessionStart + governance-lint/repo-doctor；CORE §7.1；R11。
