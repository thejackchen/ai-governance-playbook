# 施工许可不能只保护控制器

- **来源**：AIOS · 2026-08-26 · Grok 4.6/xhigh 零上下文验收
- **场景**：控制器 Codex 的 SessionStart、许可票和写入负例都通过，但项目宪法指定 Grok 为主要施工代理；Grok 与 Claude 仍直接进入没有验票的共享 PreToolUse。
- **执行者做法**：把 Codex 路径的 PASS 当成整个治理架构已闭环，又用同一控制器模型的验收结果增强信心。
- **负责人要的做法**：按真实施工面验收。谁实际能写文件，谁就必须经过同一开机许可；不同模型分别做无上下文负例，任一阻断都不能被另一模型的 PASS 抵消。
- **可泛化边界**：安全门必须覆盖最终执行者，而不只是编排器、控制器或主会话。多运行时系统应共用一个可验证的能力票据；每个入口只保留协议薄适配，不能各自复制许可逻辑。
- **载体**：CORE §7.2；universal boot admission；Codex/Claude/Grok SessionStart 与 PreToolUse 适配器；治理控制面 `alwaysClaimPaths`；三运行时缺票/过期/接线变化回归。
