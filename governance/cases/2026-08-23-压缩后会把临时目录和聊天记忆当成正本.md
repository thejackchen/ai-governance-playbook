# 压缩后会把临时目录和聊天记忆当成正本

- **来源**：AIOS · 2026-08-23 · Codex 线程压缩后把 durable worktree 当成 `/tmp` 已消失，回退到更早 commit；同日 macOS 重启清空 `/tmp`
- **场景**：长会话会自动压缩。执行者把进度只记在对话里，或把未提交改动放在 `/tmp`。压缩后记忆丢了；重启后 `/tmp` 没了。
- **执行者做法**：压缩后按聊天记忆猜路径；发现 `/tmp` 不在就从旧 commit 重建；Claude/Grok 的 PreCompact 只 `echo` 一句提醒。
- **负责人要的做法**：验证有效的经验点升母版。压缩前用机器检查并注入目录/分支/HEAD/下一步；不自动提交；人说「收口」再落盘。`echo` 不是载体。
- **可泛化边界**：所有会压缩上下文或会清空临时盘的运行时都适用。不是「压缩前自动 git commit」，也不是「机器拦压缩」——Codex 的 block 不可靠，Stop 自动删 worktree 已有反例。运行时 Goal/芯片身份也不进正本（2026-08-23 负责人：这类 corner case 不覆盖）。
- **载体**：PreCompact + `pre-compact.mjs` / `pre-compact-codex.mjs`；CORE §7.3；R13；skill `shoukou`。
