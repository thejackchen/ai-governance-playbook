# 绕过安装器手工抄治理,必漏 hook(守卫安装的东西自己没守卫)

- 日期:2026-07-28 · 来源项目:aios(AIOS 新底座)· 置信度:高(全链路实证)

## 事实

负责人问「为什么新仓没有 Stop hook?我们每个新项目都会对齐 AI governance」。排查结论:

1. **模板没错**:`adapters/claude-code/files/.claude/settings.json` 完整含三 hook;
2. **安装器没错**:`init.mjs` 会复制 filesRoot 全部文件;
3. **真因**:aios 奠基时**手工照老仓抄了一部分治理**(宪法/结构),**从未跑 init.mjs**——无 `governance.lock.json`。能自动的搬了(pre-commit 随 git 走),要手工的漏了(`.claude/` 不进 git、不随 clone 走)。
4. 后果:Stop hook 停摆数周 → landing 纪律纯靠自觉 → ROADMAP 游标冻结 13 天、CHANGELOG 断档 3 天,「无缝切换 AI」的北极星静默失效,无任何报警。

## 机制(为什么普适,不依赖 aios 特殊性)

**hook 是机器守卫,但 hook 的安装本身靠人记得——守卫安装的东西,自己没有守卫。** 任何项目只要起步时没人把 playbook 链接甩给 AI(或 AI 图省事手工抄现成仓),整条自动安装链就从起点断开,且断得无声。同族前例:提交身份漏迁、CI 载体漏迁(同一根因第三例)。

## 防线(本判例落下的载体)

1. README 顶部**北极星三条验收**:负责人随时可查任何项目「装没装(lock+doctor)/守卫在不在岗(lint hook 实效)/能否无缝接手(游标新鲜度)」;
2. `governance-lint` 新增 **hook 载体实效检查**(settings.json 存在但无 Stop 段 = 空壳假绿,warn);
3. `governance-lint` 新增 **ROADMAP 游标新鲜度检查**(正文最新日期落后最新提交 >7 天,warn);
4. 项目侧对策:被手工抄过的存量项目,补救 = 直接跑 `init.mjs --write`(SKIP 保护已有文件),再把项目级检查挂进 `policy.json` 的 fast/ciChecks——aios 已按此收编,双门全绿。

## 引用方式

新项目安装时若发现目标仓已有零散治理文件但无 lock:**这不是「装过了」,是「手工抄的」**——按 setup 附A 走收编,勿在残骸上继续手搭。
