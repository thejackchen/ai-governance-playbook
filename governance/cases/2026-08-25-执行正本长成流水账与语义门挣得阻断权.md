# 执行正本长成流水账与语义门挣得阻断权

- **来源**：AIOS · 2026-08-25 · 负责人裁决（两层门并存、绑必然事件触发、AI 语义环节接自有网关）
- **场景**：微信分支正本膨胀到 1440/1848 行、规定九段第 738 行才开始、机器门仍 PASS。治理只查「形式存在」不查「内容是否仍是唯一现役真相」；被挤出正本的热缩放知识无家=静默丢失。同期发现 hooksPath 切换后旧 pre-push 防线静默死亡 11 天，没有任何门在看「门死了」。
- **执行者做法**：每轮纠偏往同一文件追加「最新版」段落防遗漏；压缩时把有效知识连同尾气一起扔进 git 历史；机器门绿灯即认为治理健康。
- **负责人要的做法**：记账必须结账——新结论替换旧结论、被取代内容删除或降级为证据指针；确定性门与 AI 语义门两层并存，绑提交/推送/合并等必然事件；AI 结论要有阻断权必须先过 golden 正反案例套（该 block 必 block、该 pass 必 pass）；知识获取即记，但必须写得出出处与触发器，写不出=尾气不入库。
- **可泛化边界**：任何「多轮 AI 会话共写一份正本」的仓库都会得这个病，与领域无关。形状门+结账三问+投影式开工+知识路由可整套移植；语义门四规则（现役矛盾/失效当现役/语义重复/删除无家）与「golden 前置+解析失败不算 pass+本地便利远程权威」合同同样通用。
- **载体**：CORE §3 载体可验活、§5 内容语义门、§7.5 结账制与知识路由（本版下沉）；参考实现在 AIOS 仓（branch-shape / evidence-routing / semantic-review / checkHookLiveness），模板化收编为下一版候选。
