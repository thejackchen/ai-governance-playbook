# 收口

对话会被压缩，`/tmp` 会在重启时清空。未进 git 的改动和只写在聊天里的路径都不是正本。

用户说 **收口** 时：停下手头新功能，先把当前进度落到正式文件。未收口完成前不要声称可以切换或重启。

## 步骤

1. 若工作区在 `/tmp` 或 `/private/tmp`：把有效改动移到正式目录（已有的长期 worktree 或主仓库），不要在临时目录里收尾。
2. 提交今天仍要保留的改动。临时目录里未提交的内容视为会丢。不要自动提交；等人确认。
3. 在仓库正本写四行（已有执行文档/分支文件则写那里，否则写仓库内简短交接文件，不要只写在对话里）：
   - 当前目录
   - 分支
   - `HEAD` 短哈希与标题
   - 下一步（一句）
4. 跑 `git status`。不干净则继续收，或点名哪些文件故意不提交。
5. 回报：目录、分支、`HEAD`、未提交项。然后用户才可以切换工具或重启。

## 不要

- 不要把聊天摘要当成已保存进度
- 不要在 `/tmp` 里 `commit` 后当作长期正本
- 不要扩大范围去做新功能
- 不要回收 worktree
