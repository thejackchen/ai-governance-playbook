# REQ-GOV-004：项目发现能力的母版发布与安全采用

## 负责人授权与三行规格

### 语义适配升级纠偏（当前授权优先）

负责人明确：模板提供治理语义与建议，每个项目发现线上已发布新版后，由项目 AI 理解并改造本项目治理文件；不要求负责人逐项目点名能力。用无上下文 Agent 的理解与落地结果评分迭代模板。下文 v4.2.0 的“负责人显式选择才采用”限制被本段取代；禁止脚本盲目覆盖仍保留。

- 解决什么：将“禁止脚本直接覆盖”误读为“禁止 AI 自主适配”，导致版本发现、语义理解与项目落地断开。
- 怎么验收：启动或手动兜底能有界检查新版并给项目 AI 可执行的语义适配任务；保留项目事实、定制与 WIP；AI 自主选择采用/等价实现/不适用并留理由，真实项目验证与独立语义复核通过后才前移版本；无上下文实作评分覆盖定制、歧义、离线、失败和仅改版本号反例；母版测试与正常发布回读通过。
- 本次不碰：业务代码、部署、真实凭据、全局配置、主机重启、他人修改；不新建常驻更新服务，不在 hook 内调用模型或直接覆盖治理文件，不为了升级重新安装已退出的许可/巡检体系。

实施顺序：先改语义正本及发现/任务注入载体，再用隔离项目进行无上下文适配与独立评分，修复误解，最后复跑母版全验收并发布。已有 discovery 文件安装器仍是可选工具，`file-install-only` 不等于语义采用；发布新版不代表旧客户端已收到新 hook，首次发现机制缺失时须明确引导接入，不宣称自动全覆盖。

- 解决什么：AIOS 已实现的索引、分类检索、开工地图及有界环境诊断尚未进入通用母版；只推 AIOS 分支不能让其他项目采用。
- 怎么验收：通用实现没有 AIOS/Mini 业务坐标；新项目与已有项目正反测试、无历史发现验收通过；母版发布版本可回读；消费项目逐项记录实际采用文件、验证和同步状态，不能靠版本号冒充采用。
- 本次不碰：业务代码、生产部署、主机/服务重启、凭据正文、个人全局配置、他人 WIP、旧工作区自动清理；不恢复脚本盲覆盖及项目已经退出的许可或巡检机制。

负责人已确认推进母版与跨项目分发，延续 Luna Max 实现、主代理规划与独立验收。通用规则在母版，具体资产及正本入口仍在各项目。

## v4.2.0 实施与验收范围（历史基线）

下列六项仅记录 v4.2.0 上一版交付范围，保留作历史基线，不是当前语义升级的操作合同或逐仓审批清单；其中的“显式采用”只描述上一版可选文件安装边界。当前 v4.3.0 语义适配以顶部负责人授权及 [升级合同](../../playbook-update.md) 为准。

1. 盘点母版版本与消费仓；用 Git common-dir 区分独立项目和 worktree，记录实际版本、定制与脏状态。未知或冲突不自动覆盖。
2. 提炼可移植发现机制：八类任务导航、稳定资产ID/别名/标签/一跳关联、元数据按需地图、索引可达与范围源码归属检查、有界环境诊断。任务域可复用，源码根、工作线、重点对象、凭据引用和入口由项目提供；没有元数据明确报缺，不凭空登记示例机器。
3. 升级交付机制：显式、按能力采用，不因升级索引去迁移无关 admission/policy/Hook。已知受管文件以来源指纹判断可更新，未知定制或目标文件脏则拒写；计划默认只读，写入前整批检查。受管代码、项目事实、接线和版本回执分开；失败不能留下“已采用”版本。
4. 同步修正 v4.0.0 已裁决但代码未实现的自动升级退出：SessionStart 不 pull 或写入升级；旧启动入口调用也不得静默恢复自动迁移。显式升级保留，既有项目安全门不删除。
5. 完整运行母版 check/test/governance-verify 与无上下文新建/已有项目测试后发布；母版版本、SHA 与发布回读按 [ROADMAP.md](../../../ROADMAP.md) 当前游标登记，不能用版本号代替消费项目采用。
6. 消费端按只读盘点的真实清单逐个适配、验收、形成提交并核对远端；不得自动推业务发布分支。跨项目覆盖只对已识别且获安全采用的对象报告，其余明确缺口。

## 兼容与本次母版语义升级发布判据

兼容目标是保留各项目自有宪法、policy、INDEX、资产表、认领机制及运行时差异。`governance-update.mjs`
默认只做有界版本发现并输出语义适配任务；旧目录入口与 `upgrade.mjs --capability discovery --write`
仅作可选的 `file-install-only` 文件安装器，不能替代语义适配，也不能留下两份手工维护的事实或执行算法。
已有 admission、Hook、认领与两次开机合同仅适用于已经接入这些合同的项目，不向所有消费仓通用强制。

本次母版 v4.3.0 语义升级发布判据是：候选仍未发布；确定性测试、独立无上下文语义评分、固定来源/SHA
与发布回读等证据全部通过后，才可写入发布状态；不以版本号或文件复制代替采用，不改当前已记录的实际
SHA。上述判据只证明母版发布，不宣称所有消费仓采用；各消费项目若适配，按自身事实记录采用、接线和验收。
本 REQ 保持进行中，不能宣称跨项目采用完成。
